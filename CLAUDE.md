# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Purpose

This is a minimal Unity bug-repro project, not a game. It shows that Vulkan with **MSAA + the URP Depth Texture** on Meta Quest runs much worse in Unity 6.7 Beta than in Unity 2022.3.4f (before the security patch). Any change should keep the two branches identical in setup, so the only variable is the Unity version.

- `main`: Unity 6.7 Beta (`6000.7.0b3`, see `ProjectSettings/ProjectVersion.txt`)
- `2022.3.4f`: the same project in Unity 2022.3.4f (baseline)

(A local `master` branch also exists. The README only describes the two branches above.)

Repro flow (from README): build to Quest on the Android target, record FPS with OVR Metrics, switch to `2022.3.4f`, rebuild, and compare.

## Build / run

There is no C# code, no build script and no test suite. Everything under `Assets/` is assets and settings; all `.csproj`/`.sln` files are generated by Unity from packages. Builds are made from the Unity Editor (Android platform → Build to `Builds/Quest.apk`). `Builds/`, `build/`, `Library/`, `Temp/`, `Logs/` and `UserSettings/` are gitignored.

## What makes up the repro

These settings define the bug, so don't change them by accident:

- **Graphics API**: Android is set to Vulkan only, with automatic API selection off (`ProjectSettings/ProjectSettings.asset`, `m_BuildTargetGraphicsAPIs`).
- **URP asset**: `Assets/Settings/Quest_PipelineAsset.asset` has `m_MSAA: 4`, `m_RequireDepthTexture: 1`, opaque texture off and render scale 1. Its renderer is `Quest_PipelineAsset_ForwardRenderer.asset`.
- **Scene**: `Assets/MainScene.unity` contains about 100+ duplicated `Capsule` objects using `DefaultMaterial.mat`. `Assets/DepthShader.shadergraph` samples Scene Depth, which forces the depth texture to actually be used.
- **XR**: OpenXR (`com.unity.xr.openxr`) with the Meta XR Core SDK (`com.meta.xr.sdk.core`). Configuration is in `Assets/XR/` and `Assets/Resources/OculusRuntimeSettings.asset` / `OVRBuildConfig.asset`.

## Known issues

- Android build manifest problems after the 6.7 upgrade (last commit). The custom manifest was disabled by renaming it to `Assets/Plugins/Android/AndroidManifest.xml.DISABLED`. It declares both `UnityPlayerActivity` and `UnityPlayerGameActivity`, so only the one matching the Application Entry setting should be kept if it's re-enabled. Custom `mainTemplate.gradle` and `gradleTemplate.properties` are still active.
- When editing Unity YAML assets (`.asset`, `.unity`, `.mat`) by hand, keep the matching `.meta` files and GUIDs unchanged.
- Builds and package tooling generate and delete some tracked files: `Assets/Resources/PerformanceTestRunInfo.json` / `PerformanceTestRunSettings.json` (Performance Testing package), `Assets/StreamingAssets/RuntimeActionBindings.json`, and extra `preloadedAssets` entries in `ProjectSettings.asset`. A diff in these is usually build churn, not an intended change. On `main`, the forward renderer's `xrSystemData` being `{fileID: 0}` is expected: Unity 6 moved the XR shaders into `UniversalRenderPipelineGlobalSettings.asset` (`UniversalRenderPipelineRuntimeXRResources`).
- Some settings already differ between branches and break parity: the `MetaXRFeature Android` OpenXR feature is on in `2022.3.4f` but off on `main`, and Android graphics jobs are off in `2022.3.4f` but on on `main`.
